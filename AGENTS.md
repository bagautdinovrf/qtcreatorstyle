# Repository Guidelines

## Структура проекта

Репозиторий содержит цветовые схемы редактора Qt Creator. Все файлы находятся в корне:

- `creator-dark_copy.xml` — схема `MyDark`.
- `inkpot_copy.xml` — схема `MyInk`.
- `porcelain-light.xml` — светлая схема `Porcelain Light`.
- `paper-light.xml`, `linen-light.xml` — светлые схемы `Paper Light` и `Linen Light`.
- `README.md` — путь установки схем в Windows.

XML-файлы являются основными ресурсами проекта. Каталогов исходного кода, тестов и отдельных изображений нет. Каждая схема содержит корневой элемент `style-scheme` и элементы `style` для текста, подсветки синтаксиса, диагностики и просмотра различий.

## Команды разработки и проверки

Сборка и установка зависимостей не требуются. Выполняйте команды PowerShell из корня репозитория.

Проверка корректности XML во всех схемах:

```powershell
Get-ChildItem -File *.xml | ForEach-Object {
    $document = [System.Xml.XmlDocument]::new()
    $document.Load($_.FullName)
}
```

Проверка пробельных ошибок в изменениях: `git diff --check`.

Для локальной установки одной схемы:

```powershell
$styles = Join-Path $env:APPDATA 'QtProject\qtcreator\styles'
New-Item -ItemType Directory -Force -Path $styles | Out-Null
Copy-Item .\creator-dark_copy.xml -Destination $styles
```

Перед заменой установленной схемы сохраните её копию. Затем выберите `MyDark` в настройках цветовой схемы редактора Qt Creator. Для `MyInk` скопируйте `inkpot_copy.xml`.

## Стиль и именование

Сохраняйте XML в UTF-8 с существующим объявлением версии. Используйте два пробела для отступа, один самозакрывающийся элемент `style` на строку и существующий порядок элементов. Цвета записывайте как `#rrggbb`, логические атрибуты — как `true` или `false`.

Не переименовывайте ключи стилей, например `CurrentLineNumber` или `Doxygen.Comment`: они обозначают категории Qt Creator. Сохраняйте имена существующих файлов и схем; новым схемам задавайте отличимое имя. Форматтер и линтер не настроены. Избегайте массового переформатирования при изменении отдельных цветов.

## Проверка изменений

Автоматического тестового набора и требований к покрытию нет. После проверки XML загрузите изменённую схему в Qt Creator. Проверьте текст, строки, комментарии, текущую строку и её номер, выделение, поиск, предупреждения и ошибки. Для изменений QML или цветов различий откройте соответствующий пример. Убедитесь, что изменённые элементы читаются на фоне схемы.

## Коммиты и pull request

История использует короткие описания изменений на русском и английском, например `Изменен цвет строк` и `Update README.md`; обязательных префиксов нет. Делайте отдельный коммит для каждого логически связанного изменения.

В pull request укажите схему, изменённые категории, причину и результаты проверки. Для визуальных изменений приложите снимки до и после и версию Qt Creator. При наличии связанной задачи добавьте ссылку.

## Инструкции для агентов

Работать можно на любом языке; отвечайте пользователю по-русски.
